# VaSports · 维阿斯场馆预约

微信原生小程序内部演示工程。正式入口为 miniprogram/app.json，在微信开发者工具中打开本目录，使用现有 AppID 编译。无需开通云开发或构建 npm。不要运行历史初始化脚本 tools/build-demo.py，它会覆盖现行页面的增量修改。

## 当前范围

四个 Tab：首页、场馆、我的预约、我的。支持羽毛球 8 场、乒乓球 10 台、未来 7 天场次、预约与取消、库存恢复、本机持久化及独立预约核销码。核销码由本地 QR 编码库生成，不请求在线二维码服务。用户页面没有自行核销入口。

当前库存及用户身份均为本地模拟；没有微信登录、真实学校库存、收费、支付、真实后台或跨设备核销。本机随机 userId 不是微信身份认证。用户界面精简技术文案不代表产品已可以向公众开放真实预约。

## 工程与验证

- miniprogram/pages/：16 个原生页面，包括 redemption-code。
- miniprogram/components/：场馆、场位、时段、日期、预约卡片及空状态。
- miniprogram/services/：业务服务与可替换本地 provider。
- miniprogram/mock/：场馆及库存规则。
- miniprogram/utils/qr.js：真实二维码编码适配。
- tests/：预约、核销、迁移及核销页生命周期测试。
- [核销契约](docs/REDEMPTION_CONTRACT.md)：字段、状态、接口、安全边界及旧后端只读审计。

运行 npm test 与 npm run check。这两项不能替代微信开发者工具实际编译、点击和真机验收。截图及二维码独立解码证据保存在 05_Output/redemption-20261002/，不属于小程序运行目录。

Storage key 已迁移为 vasports.reservations.v1（旧命名空间只读兼容；保留旧数据，不清空），schema 原位升级到 version 3，保留已有预约。保留持久化 userId、稳定 courtId、凭证和核销事件，新增登录态与学生/访客资料。默认演示账号 A 唯一关联旧预约，账号之间共享库存、隔离个人记录。不要通过清空 Storage 处理迁移问题。

本地核销凭证默认有效 60 秒；核销时间窗独立配置为开始前 30 分钟至结束前，仅用于模拟验证，不代表任何学校规则。页面到期会重新获取凭证，隐藏时停计时并清除旧图。结束与已核销分别处理；核销不释放库存。

## 登录与身份验收

已新增原生登录引导、绑定手机号、两类身份选择、学生核验、访客资料和个人资料页面。使用明确的 LOCAL_DEMO 配置，模拟微信登录入口但不创建或伪造 OpenID；手机号和核验使用虚构数据。真实 HTTP provider 已写好适配方法，但没有独立服务端或账号权限证据，尚未联调，不会自动降级成演示成功。

见 [身份接口契约与测试数据](docs/IDENTITY_CONTRACT.md)。账号 A 为学生用例，账号 B 为访客用例。退出登录不删除预约。要从头演示：登录页→切换账号→新建体验账号；无需清除 Storage。不要向内部演示填写真实个人资料。

核销码页仅移除用户/预约等内部编号及对应容器，二维码主体、短时刷新和数据关联保留。本轮实际截图与解码结果位于 05_Output/identity-20261002/。
